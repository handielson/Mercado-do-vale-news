# v1.1.95 — Fix: Atributos Searchable Removidos no Retry da Shopee

**Data:** 2026-06-22  
**Branch:** codex/publish-delivery-ops-20260614

## Problema

Ao publicar um produto na Shopee, quando a API retornava um erro no primeiro `add_item`, o sistema fazia um retry removendo "atributos com valores customizados" via `pruneOptionalCustomAttributePayload`. O critério usado era:

```js
const hasCustomValue = values.some((value) => Number(value?.value_id || 0) === 0);
```

Isso removia **todos** os atributos com `value_id === 0`, incluindo atributos do tipo **searchable/text** (como **Potência - shopee:100105** e **Tensão de Entrada - shopee:100323**) que legitimamente têm `value_id: 0` com `original_value_name` preenchido (ex: "100W", "110V").

## Correção

`pruneOptionalCustomAttributePayload` em `ShopeePage.tsx` agora só considera um valor "inválido" se `value_id === 0` **E** `original_value_name` também está vazio:

```js
const hasInvalidCustomValue = values.some((value) =>
    Number(value?.value_id || 0) === 0 && !String(value?.original_value_name || '').trim()
);
```

## Arquivos Alterados

- `pages/admin/settings/ShopeePage.tsx` — função `pruneOptionalCustomAttributePayload` (linha ~534)

## Impacto

- Atributos searchable (texto livre, com unidade como W, V, ML) agora são preservados no retry
- Atributos realmente inválidos (value_id=0 e sem nome) ainda são removidos corretamente
- Não há mudança visual — apenas comportamento de envio para API Shopee
