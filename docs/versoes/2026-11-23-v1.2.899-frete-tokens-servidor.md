# v1.2.899-frete-tokens-servidor

Data: 23/11/2026 · Status: publicada (API e site) · Robô sem mudança.

## Problema
`GET /shipping/settings` é público (o site lê antes de calcular o frete) e devolvia `melhor_envio_token` e `frenet_token` em texto. O cálculo rodava no navegador mandando o token para `/api/shipping`, e a geração de etiqueta (`action=label`, que gasta saldo do Melhor Envio) era pública com o token no corpo.

## Mudanças (shipping-secrets-v1)
- `services/shippingSecrets.cjs`: leitura pública troca cada token por `configurado-no-servidor` e acrescenta `melhor_envio_configured`/`frenet_configured`; `withStoredShippingToken` põe o token guardado no banco na chamada (o do navegador é ignorado quando há token guardado).
- `scripts/deploy-shipping-secrets.cjs` (+ `--shipping-secrets-only|check` no `deploy-vps-server-only.cjs`), ganchos em `vps_server.js/.cjs`:
  - GET `/shipping/settings` → `publicShippingSettings(row)`;
  - PATCH: token vazio ou o marcador não sobrescreve o token guardado (a tela de admin pode salvar sem apagar);
  - POST `/api/shipping`: `action=label` exige login de admin (401 sem); demais ações com o token do banco.
- `components/shipping/FreightCalculator.tsx`: a etiqueta manda o login de admin.

## Validação
- `tmp-tests/shipping-secrets.test.cjs`: 3 ok.
- Produção: `/shipping/settings` devolve o marcador (sem token); cotação Melhor Envio e Frenet funcionam com o marcador; etiqueta sem login → 401.
- API: backup `/var/www/mdv-api/backups/shipping-secrets-1795440256104`. Site: release `20261123-102459-v1-2-899-frete-tokens` (anterior `20261123-101359-v1-2-898-frete-busca`).

## Pendente (dono)
Os tokens ficaram públicos até hoje: gerar tokens novos no painel do Melhor Envio e da Frenet e colar em Admin › Frete (o campo aceita o novo; vazio mantém o atual).
