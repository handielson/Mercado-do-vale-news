# v1.2.867-bot-retentativa-estado

Data: 18/11/2026. Branch: `main`. Só o robô do WhatsApp (n8n). Site e API sem mudança.

## O caso

Cliente mandou "Boa tarde" e, 11 s depois, "Onde fica sua loja" (18/11, 18:14). A primeira foi respondida. A segunda montou a resposta certa (endereço + link do mapa + "Se precisar de ajuda para chegar…"), mas a gravação do estado da conversa foi recusada por **conflito de revisão**: a primeira mensagem ainda estava rodando e subiu a revisão de 3 para 4. O fluxo tenta de novo (até 2 vezes), mas as 3 tentativas pediram a revisão 3 e foram recusadas; aí a resposta foi descartada sem enviar nada (regra: não responder com estado que não foi salvo). A resposta foi enviada manualmente pela API do WhatsApp em 18/11 ~19:05.

## Causa

`Estado Conversa - Preparar` juntava `{ ...contexto da retentativa, ...$json }`. O especialista da Loja (`Loja - Localizacao`) reconstrói os dados a partir do `Parse Classificacao`, que tem a revisão velha, e essa cópia sobrescrevia a revisão nova da retentativa. O Agente Geral devolve só o texto, por isso não era afetado.

## Correção (`conversation-state-rebase-revision-v1`)

Na retentativa (`conversationStateRebase === true`), revisão, contador de tentativas, marca de rebase e controle vêm sempre do contexto da retentativa. Primeira tentativa e grafo do workflow não mudam; só o nó `Estado Conversa - Preparar`.

- `scripts/n8n-state-rebase-revision.cjs` (patch), `scripts/deploy-n8n-state-rebase-revision.cjs` (dry run / `--apply`, backup criptografado, CAS e hash).
- `tmp-tests/n8n-state-rebase-revision.test.cjs`: retentativa grava contra a revisão 4 com a saída da Loja; fluxo antigo reproduz o defeito (3); primeira tentativa e Agente Geral inalterados; patch idempotente e só no Preparar. Roda com `MDV_N8N_SALES_SNAPSHOT` (grupo n8n do `npm run test:tmp`).
