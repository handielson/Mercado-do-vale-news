## Correção

- Quando `salesPostList` já expirou, o pedido de foto usa o modelo e a cor recuperados pelo classificador para consultar novamente o catálogo.
- Uma resposta numérica imediatamente posterior ao pedido de confirmação só pode reutilizar um SKU exato presente em um link recente do produto.
- Resultados ambíguos não escolhem o primeiro produto: o bot pede modelo e cor, sem repetir a confirmação pelo número antigo.
- A consulta continua usando `helpers.httpRequest`, compatível com o task runner do n8n.

## Evidência

- A execução 8071 recuperou `wp58 pro laranja` e o item 36, mas não encontrou estado de lista e repetiu a confirmação.
- A execução 8072 classificou a resposta `36` como `pedir_foto`, porém caiu no mesmo fallback porque `salesPostList` continuava ausente.
- A API retorna um único Wp58 Pró laranja e quatro imagens resolvidas para o SKU exato `W58P24816512L`.

## Validações

- Teste regressivo cobre recuperação por modelo/cor, resposta numérica ligada a SKU exato, resultado ambíguo, falha HTTP e URLs de imagem permitidas.
- Simulação somente leitura executa o código ativo real do nó com os dois formatos observados nas execuções 8071 e 8072.
- O patch é idempotente, compila antes da aplicação e cria backup dedicado do workflow.
- Nenhuma mensagem é enviada automaticamente durante a publicação.
