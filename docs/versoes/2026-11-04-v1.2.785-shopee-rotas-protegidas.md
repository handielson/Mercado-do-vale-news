# v1.2.785-shopee-rotas-protegidas

- Data: 04/11/2026
- Branch: `main` (base `bc562530`)
- Site: sim. API: sim.

## Problema
`/api/shopee-catalog` e `/api/shopee-actions` estavam registradas sem `preHandler` e respondiam pela internet sem login (conferido: GET público de `get_item_base_info` retornou HTTP 200 com dados do anúncio). As mesmas rotas aceitam `update_price`, `update_stock`, `add_item` e ações de pedido.

## O que mudou
- API (`vps_server.js` e `vps_server.cjs`): as duas rotas usam `preHandler: requireSyncKeyOrAdmin` (admin Bearer ou `x-sync-key`).
- Front: `services/shopeeApiAuth.ts`, instalado no `index.tsx`, acrescenta o token do admin somente em chamadas do próprio site para essas duas rotas (as telas usam `fetch` direto em ~40 pontos). Outras rotas e outros domínios não recebem o token.
- Agente de impressão (`scripts/shopee-auto-print.cjs`) já envia `x-sync-key`; sem mudança.
- Ordem de publicação: site antes da API, para o admin nunca ficar sem acesso.

## Validações
- `node --test tmp-tests/shopee-api-auth.test.mjs` (novo: rotas protegidas nos dois servidores, proteção não pode sumir, wrapper só nas rotas certas e nunca para outro domínio).
- `vps-shopee-actions-read`, `vps-shopee-actions-refresh`, `vps-shopee-catalog-read` atualizados para exigir a proteção; demais 14 `vps-shopee-*-static` ok.
- Chamadores mapeados: logs do nginx mostram só navegador (admin) + agente; nenhum código de servidor/cron chama essas rotas por HTTP.
