# v1.2.811-ficha-nomes-publicos

- Data: 06/11/2026
- Branch: `main`
- Pedido do usuário (06/11): "temos o campo para preencher, na pagina do modelo, veja o pq está com essas 2 fontes e mude para uma com acento que é a forma correta". Na página do Pad 6, o admin via "Resistência" e o cliente via "resistencia".

## Causa (as 2 fontes)
- A ficha da página do produto (`pages/store/PublicProductPage.tsx`) pega o nome de cada campo no cadastro de campos (`custom_fields`, onde está "Resistência").
- Esse cadastro só era lido quando o visitante era admin (`customer_type === 'ADMIN'` → `/table-data/custom_fields`, que responde 403/401 para os outros).
- Para o cliente, sem o cadastro, a página usava a própria chave (`resistencia`, com `_` virando espaço), sem acento.

## O que entrou
- **Uma fonte só para os nomes** (`public-spec-labels-v1`):
  - API: nova rota pública `GET /public/spec-labels` em `vps_server.js` e `vps_server.cjs`. Devolve só `{ chave: nome }` dos campos de ficha (`basic`, `spec`, `logistics`); campos fiscais, de preço, sem nome ou com `_` na frente ficam fora. Cache público de 60 s (CDN 300 s). A rota está na lista de leituras sem login.
  - Site: `services/vpsTransport.js` lê a rota direto da API, como as outras leituras públicas.
  - Página do produto: busca os nomes nessa rota para todo mundo (cliente e admin), no lugar da leitura que só funcionava para admin.
- Resultado: o nome que aparece é sempre o do cadastro do campo, o mesmo usado no admin e na página do modelo ("Resistência").
