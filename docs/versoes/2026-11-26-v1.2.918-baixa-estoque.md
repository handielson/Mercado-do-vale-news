# v1.2.918-baixa-estoque (26/11/2026)

- Pedido do dono: baixa administrativa de produtos ("identificado com defeito na hora da venda"); "Avaria sai do estoque e vai para o lixo, porém preciso de outras opções, como retirada para uso na loja, coloca uma opção para escrever quem deu a baixa e o motivo, o motivo deve aparecer no bling".
- API (stock-write-off-v1): `services/stockWriteOffs.cjs` + `scripts/deploy-stock-write-offs.cjs` (`node deploy-vps-server-only.cjs --stock-write-offs-only`).
  - `GET /stock-write-offs/kinds`, `GET /stock-write-offs`, `POST /stock-write-offs` (sync key ou admin).
  - Tipos: Avaria / defeito (descarte), Retirada para uso na loja, Brinde / doação, Perda / extravio, Outro. Motivo e "quem deu a baixa" obrigatórios.
  - Primeiro lança SAÍDA no Bling (mesmo depósito da venda do PDV) com observação `Baixa administrativa MdV - <tipo> | Motivo: ... | Responsável: ... | IMEI: ...`; se o Bling recusar, nada muda no MdV. Depois baixa o saldo do local (movimento `write_off`) ou, com IMEI, marca o aparelho `written_off` e recalcula; se o MdV falhar, estorna no Bling.
  - Recusa kit/combo e produto sem vínculo com o Bling. Tabela `stock_write_offs` guarda o histórico.
  - Publicada 26/11 ~20h; backup `/var/www/mdv-api/backups/stock-write-offs-1795733388301`.
- Site: tela `/admin/estoque/baixas` (menu Produtos & Estoque → Baixa de estoque): busca por nome/SKU ou IMEI, tipo, quantidade, quem deu a baixa (lembrado no navegador), motivo e últimas baixas.
- Proteção: `tmp-tests/stock-write-offs.test.cjs`.
