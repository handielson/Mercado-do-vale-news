## Alterações

- O controlador de conversa reconhece de forma determinística quando o cliente corrige uma data logo após receber os parabéns automáticos.
- A data informada pelo cliente é preservada no contexto e a resposta pede desculpas pelo envio incorreto, sem tratar a mensagem como simples agradecimento.
- A correção é encaminhada para a equipe pelo fluxo persistente de handoff já existente, que pausa o bot por duas horas.
- O pedido genérico de atendente passa a usar duas frases curtas e objetivas, sem repetir “vou chamar” nem fazer afirmações contraditórias sobre disponibilidade.

## Evidência do incidente

- A execução analisada recebeu o histórico correto, inclusive os parabéns e a correção `11/10`.
- O classificador devolveu `fallback` e o agente geral respondeu como se tivesse recebido apenas um agradecimento.
- A causa estava na ausência de uma decisão determinística para correção de data, não na memória ou no envio do WhatsApp.
- O cadastro já estava com a data correta quando foi conferido; nenhum dado de cliente foi alterado por esta publicação.
