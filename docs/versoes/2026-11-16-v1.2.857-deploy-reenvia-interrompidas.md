# v1.2.857-deploy-reenvia-interrompidas

Data: 16/11/2026. Branch: `main`. Só os scripts de publicação do n8n (máquina local). Robô, site e API sem mudança.

## Caso real (16/11, 12:08)

Na publicação da v1.2.856, o script confirmou "nenhuma execução ativa" e, 3 s depois, desligou o n8n. A mensagem "Vocês trabalham com boleto?" chegou nesse intervalo, foi cortada no meio ("Task request timed out") e a cliente ficou sem resposta. Foi reprocessada à mão às 12:15 e o bot respondeu normal (PayJoy, link da análise).

## O que muda

`scripts/deploy-n8n-meta-attendance.cjs` (`interrupted-replay-v1`), usado por todos os `deploy-n8n-*.cjs` via `callRemote`:

- Quando o runner do n8n volta (fim do deploy ou recuperação depois de falha), o script espera o n8n ficar pronto e reenvia ao webhook do WhatsApp as mensagens de cliente que morreram desde 2 min antes do início do deploy.
- Só reenvia: `messages.upsert` de conversa privada, vinda do cliente, com ID de mensagem, status `crashed` ou erro de interrupção (timeout do runner, conexão), e que ainda não enviou nada ao cliente.
- Não reenvia se uma execução posterior com a mesma mensagem já terminou com sucesso, nem a mesma mensagem duas vezes.
- Roda uma vez por deploy; falha no reenvio não derruba o deploy. O resumo vai para o stderr só com IDs de execução (sem dados de cliente). `MDV_N8N_SKIP_INTERRUPTED_REPLAY=1` desliga.
