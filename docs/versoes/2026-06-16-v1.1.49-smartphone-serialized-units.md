## Resumo

- O PDV agora agrupa smartphones serializados por `model_id`, RAM, armazenamento e cor quando a variante esta completa.
- Isso corrige cadastros de smartphones com SKU legado ou errado, mantendo cores e capacidades separadas.
- Produtos legados sem unidade deixam de aparecer como card separado quando existe o cadastro canonical com unidades disponiveis.
- Foi criado `scripts/rebuild-smartphone-serialized-units.cjs` para dry-run, resumo e reconstrucao controlada de unidades a partir de IMEIs antigos em `product.specs`.

## Dados Corrigidos Na VPS

- Dry-run geral encontrou 77 smartphones com IMEI legado em `product.specs`.
- A reconstrucao planejou 70 unidades em 47 grupos de variante.
- A API inseriu 63 unidades novas.
- A API recusou 7 entradas por `duplicate_serialized_identifier`, pois os IMEIs ja existiam em `units`.
- No caso reportado, `RN15P8256T` ficou com 2 IMEIs disponiveis e `RN15P8256P` ficou com 1 IMEI disponivel.
