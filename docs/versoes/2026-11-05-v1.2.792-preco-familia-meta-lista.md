# v1.2.792-preco-familia-meta-lista

- Data: 05/11/2026
- Branch: `main`
- Site: sim. API: sim (só `services/metaAttendanceReplies.cjs`). n8n/impressão: não.

## Cadastro de família ("Confira os preços de C17 Plus - Branco: use valores válidos acima de zero")
- Causa: a API devolve `price_retail`/`price_wholesale` como texto DECIMAL (`"130000.00"`). Os rascunhos de cor herdam o preço do pai (`"0.00"`), e `partitionSmartphoneFamilyRowsForSave` só aceitava número inteiro. Qualquer salvamento da família (ex.: trocar a foto do pai) travava.
- `components/products/familyRegistration.js` (`family-price-normalize-v1`): `familyPriceValue` converte texto numérico; as linhas novas vão com número. Texto não numérico, negativo ou fracionado continua bloqueado.
- Teste: `tmp-tests/family-registration.test.mjs` (caso C17 Plus: Branco com "0.00" fica no rascunho; Verde com "130000.00" salva).

## Página do produto: preço duplicado
- `pages/store/PublicProductPage.tsx` (`pdp-no-duplicate-price-v1`): sai o preço ao lado de "Opções disponíveis" (adicionado na v1.2.775); fica só o quadro "À vista no Pix".

## Facebook/Instagram: lista cortada no meio do produto
- Causa: `normalizeResponse` dividia o texto a cada 900 caracteres (limite do Instagram), sem olhar o conteúdo.
- `services/metaAttendanceReplies.cjs` (`meta-split-product-boundary-v1`): `splitMetaText` divide em blocos (marca + item; cada item "N." até o separador). Só quebra um bloco maior que 900 sozinho por linha/espaço. Separador nunca no início ou no fim de uma mensagem.
- WhatsApp: não corta por tamanho (só nos `[[MSG]]`), e cada mensagem tem até 3 aparelhos (v1.2.791). Sem mudança.
- Teste: `tmp-tests/meta-attendance-replies.test.cjs` (21 produtos com descrição: cada mensagem ≤ 900, termina no fim de um produto, item inteiro em uma só mensagem, marca junto do primeiro item).
