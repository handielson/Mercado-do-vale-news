# v1.2.854-status-sem-reenvio

Data: 13/11/2026. Branch: `main`. Escopo: API (Status do WhatsApp — conferência automática). Site sem mudança.

## Motivo

Vídeo agendado das 08:00 de 13/11 (entrega `3e8610b7-f149-4a2d-8271-6b8d53e1fa9a`) saiu **3 vezes** no Status do WhatsApp: 08:01, 08:10 e 08:21, todas com HTTP 201 do WAHA. O WAHA responde 201 sem id, então a entrega caía na conferência da v1.2.849; a leitura de `status@broadcast` volta sempre vazia (mesmo com os Status no ar), a conferência concluía "não publicado" em 2 leituras e reenviava até o limite de 3.

## O que muda (`whatsapp-status-no-resend-v1`)

- `services/whatsappStatusSender.cjs`: 2xx sem id grava o marcador `[WAHA_ACEITO] HTTP <status>` na mensagem (continua `WAHA_STATUS_OUTCOME_UNCERTAIN`, o agendador não muda).
- `services/whatsappStatusReconcile.cjs`:
  - leitura vazia, sem nenhum Status próprio recente, ou "Chat not found for status@broadcast" → `unknown` (conferência manual), nunca `not_published`;
  - `not_published` só quando a leitura traz Status próprios recentes e nenhum bate com a entrega;
  - entrega com `[WAHA_ACEITO]` e sem confirmação na leitura → marcada **publicada sem confirmação** (`last_error` explica, check `unknown`), sem `queueRetry`, inclusive pelo botão do admin.
- Reenvio automático segue existindo só para envio sem 2xx (timeout/5xx) com prova de que não saiu.

## Mitigação já aplicada

`SOCIAL_STORY_WHATSAPP_MAX_ATTEMPTS=1` no `.env` da `mdv-api` (backup `/root/backups/mdv-api.env.*.bak`) + `pm2 restart mdv-api --update-env` em 13/11 ~09:25. Mantido. Pode voltar para 3 (ou ser removido) quando a leitura do WAHA passar a enxergar os Status publicados.
