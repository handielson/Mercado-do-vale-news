# v1.1.107-shopee-video-polling-retry-fix

- data: 2026-06-23
- branch: main
- release_vps: pendente
- commit: a definir apos publicacao

## Motivo

Ao importar produto com video para a Shopee, o add_item falhava com:
`product.error_busi: external system business error : invalid or expired vid`

Causa raiz: o video_upload_id estava sendo usado no add_item antes de a Shopee
terminar de transcodificar/validar o video. Tres defeitos combinavam:

1. Servidor (vps_server.js/cjs, server.js): polling pos-upload de apenas 12 x 2s = 24s,
   insuficiente para videos maiores que precisavam de ~40s+.
2. Frontend (ShopeePage.tsx): tratava HTTP 408 video_upload_timeout como sucesso e
   devolvia o ID prematuro ao chamador.
3. Fluxos de publicacao/edicao: usavam o ID sem retry, passando direto ao add_item.

## O que mudou

### Servidor (vps_server.js, vps_server.cjs, server.js)
- Polling de get_video_upload_result estendido de 12 x 2s (24s) para 30 x 3s (~90s)
  apos complete_video_upload, dando tempo suficiente para a Shopee transcodificar.

### Frontend (ShopeePage.tsx)
- Removido o bloco que transformava 408 video_upload_timeout em sucesso (return data).
  Agora 408 lanca erro como qualquer !res.ok.
- Novo helper `isShopeeVideoStillProcessingMessage`: identifica video ainda em
  processamento (video_upload_timeout, "ainda em processamento", "invalid or expired vid",
  "request vid is abnormal").
- Fluxo de publicacao (sync): upload_video agora usa `postShopeeDebugWithRetry` com
  retries=3, delaysMs=[6s, 10s, 15s] e shouldRetry=isShopeeVideoStillProcessingMessage.
- Fluxo de edicao (update_item): substituido fetch cru por postShopeeDebugWithRetry com
  a mesma politica de retry.
- Fluxo de retry do add_item (isShopeeVideoDispatcherError) mantido como estava,
  mas agora raramente sera alcancado pois o upload_video ja entrega ID validado.

### Teste de regressao
- tmp-tests/shopee-video-retry-no-premature-vid-static.test.mjs: valida que:
  - polling do servidor tem >= 30 tentativas
  - 408 NAO e tratado como sucesso no frontend
  - helper isShopeeVideoStillProcessingMessage existe e cobre todos os padroes
  - ambos os fluxos usam postShopeeDebugWithRetry com shouldRetry
