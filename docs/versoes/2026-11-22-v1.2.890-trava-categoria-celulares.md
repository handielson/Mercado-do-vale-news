# v1.2.890-trava-categoria-celulares

Data: 22/11/2026 · Status: publicada (banco MySQL) · Site, API e robô sem mudança.

## Problema
Produto cadastrado na categoria principal **Celulares** (em vez de uma subcategoria) some da lista do robô, que busca **Smartphones**. Caso Redmi 15C 4GB/256GB (propostas #12–#17).

## Mudança
- 5 produtos saíram da raiz Celulares para Smartphones: RC154256A, RC154256V (com estoque), RC158256P, R15C4256 (sem estoque) e o pai da família Redmi A5 (MODELO-6D1E07657065F6F43F3A; as 10 variações já estavam em Smartphones). Backups em `/var/www/mdv-api/backups/categoria-*.json`.
- `scripts/apply-celulares-category-guard.cjs` (celulares-category-guard-v1): triggers `mdv_products_celulares_root_ins` e `mdv_products_celulares_root_upd` (BEFORE INSERT/UPDATE em products). Inserir ou **mudar** um produto para a raiz Celulares dá erro "Categoria Celulares nao recebe produto: escolha a subcategoria…". Vale para admin, Bling e API. Atualizar estoque/preço não é afetado.
- Criadas como root via socket (log binário exige), como os triggers do diário de unidades.
- Fora do escopo: categorias extras (`product_categories`) e as outras categorias principais que têm produtos direto (Ferramentas, Caixas de som etc. — uso normal hoje).

## Validação
- O script confere numa transação desfeita: mover para a raiz → bloqueado; inserir na raiz → bloqueado; update comum → ok.
- Biblioteca de erros #229 atualizada.
