## Pedido
Em Movimentar estoque, ao ler o código de barras já mostrar o produto com a quantidade e o destino; faltava criar outro local de estoque.

## Mudanças no app (`android/admin-estoque`)
- "Ler código de barras do produto" virou a primeira ação da tela; a pesquisa por nome/SKU/EAN continua abaixo.
- Leitura casa exatamente com EAN (ou SKU). Com um único local de origem, abre direto a tela de movimentação (foto, nome, SKU, origem, quantidade, destino por QR ou lista, "Confirmar movimentação"). Com várias origens, lista os locais com saldo para escolher. Produto sem saldo mostra aviso.
- Voltar ou concluir a movimentação aberta pela leitura retorna para a tela de leitura, pronta para o próximo produto.
- "+ Criar novo local de estoque": card na tela inicial e botão na escolha do destino. Pede nome, código opcional e depósito (lista de `GET /stock-locations/deposits`, o depósito da origem vem pré-selecionado; oculto quando só há um). Envia o mesmo payload do admin web (`deposit_id, name, code, description, is_default=false`) para `POST /stock-locations/locations`; na movimentação, o local criado já vira o destino.
- `StockLocationBox.parseOne` lê o local retornado.

## API
- `vps_server.js` / `vps_server.cjs`: `POST /stock-locations/locations` de `requireSyncKey` para `requireSyncKeyOrAdmin` (o app usa token admin, nunca a chave de sync). Criar/editar depósito e editar local continuam só com a chave.
- Sem essa publicação, criar local pelo app retorna 401 ("Unauthorized"); o restante do app funciona com a API atual.

## Testes

Todas passam, exceto a verificação preexistente `vps_server.js` == `vps_server.cjs`, que já falhava no `main` antes desta versão (arquivos diferem desde commits anteriores).
