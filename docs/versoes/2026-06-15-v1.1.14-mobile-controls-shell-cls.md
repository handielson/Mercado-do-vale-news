## Motivo

O PageSpeed mobile gerado em `14/06/2026 22:16 BRT` apontou CLS `0.612`.
A maior troca de layout (`0.548`) veio do bloco do catalogo que contem `Filtros`, `Compartilhar Catalogo` e chips de colecoes.
O LCP tambem ficou alto (`5.3s`) por descoberta tardia da imagem de banner, apesar da imagem ja estar marcada como prioridade alta quando renderizada.
O frontend ja anunciava fontes AVIF/WebP para banners, mas a VPS ainda nao gerava esses derivados durante upload.

## O Que Entrou

- O shell inline do `index.html` agora reserva a linha mobile dos controles do catalogo antes dos chips.
- O fallback React em `App.tsx` agora reserva a mesma linha antes das colecoes carregarem.
- A ordem visual do shell foi alinhada com o catalogo real mobile para reduzir deslocamento durante hidratacao/carregamento.
- O teste `tmp-tests/catalog-mobile-loading-shell-cls-static.test.mjs` foi ampliado para bloquear a remocao ou inversao dessa reserva.
- `App.tsx` agora aquece os banners publicos quando a rota inicial e catalogo.
- `services/bannerService.ts` agora reutiliza uma requisicao em voo/cache curto de banners ativos para evitar chamada duplicada entre warm-up e carrossel.
- O teste `tmp-tests/catalog-banner-prefetch-static.test.mjs` protege o warm-up e o reuso da requisicao.
- `vps_server.js` e `vps_server.cjs` agora geram derivados WebP/AVIF apos uploads de produto, banco de imagens e banner.
- O cache imutavel da VPS agora so se aplica a derivados com larguras conhecidas (`320`, `480`, `768`, `800`, `1280`).
- `deploy-vps-server-only.cjs` garante `sharp` no diretorio remoto da API antes de reiniciar o PM2.
- Os testes `tmp-tests/vps-upload-derivatives.test.mjs` e `tmp-tests/vps-server-deploy-sharp-static.test.mjs` protegem esse fluxo.
