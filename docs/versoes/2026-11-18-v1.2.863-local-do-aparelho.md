# v1.2.863-local-do-aparelho

Data: 18/11/2026. Branch: `main`. Site + API + nginx + ajuste de dados. Spec: `docs/superpowers/specs/2026-11-18-historico-do-aparelho-design.md` (Parte 2). Plano: `docs/superpowers/plans/2026-11-18-local-do-aparelho.md`.

## Como era

O saldo por local de produto com IMEI já era recalculado a partir dos aparelhos (`syncSerializedProductStockFromUnits`): aparelho sem local contava em Loja Principal / Estoque Geral. Só 18 de 86 disponíveis tinham local. Transferir celular por quantidade mexia no saldo, mas o próximo recálculo desfazia.

## O que entrou

- **Todo aparelho nasce no Depósito / Entrada / Conferencia** quando a entrada não informa o local (`POST /units`, `/units/batch`, entrada por foto; a Entrada única já exige local).
- **Saiu de uma venda (vendido → disponível), volta para o Depósito / Entrada / Conferencia** para conferir, com evento "Foi para conferência".
- **Tela "Transferir aparelhos"** (`/admin/aparelhos/transferir`): escolhe depósito e local de destino, bipa ou digita IMEI/serial, vê onde cada um está, transfere tudo de uma vez. A API (`POST /admin/units/transfers`) trava só os aparelhos escolhidos, por id e em ordem, recusa vendido/oculto/RMA/inexistente/já no destino sem mudança parcial, e devolve 409 "tente de novo" em concorrência.
- **Transferência por quantidade de produto com IMEI é recusada** com a orientação de usar Transferir aparelhos.
- **Página do aparelho** mostra "Transferido · origem → destino", "Local definido" e "Foi para conferência", com quem fez e o motivo.
- **Lista "Produtos com saldo sem IMEI"** na página Aparelhos (`GET /admin/units/stock-mismatches`).
- Tabela `unit_events` (só inclusão; triggers criados como root com `scripts/unit-events-triggers-sql.cjs`), criada no boot da API.
- `ensureIncomingStockLocation` só regrava o Depósito quando algo difere (não prende a linha dentro das transações de entrada).

## Fora desta versão

Devolução de itens com recibo/comprovantes (Parte 3). Melhorias pequenas adiadas: backfill concorrente com venda, backfill aplicar só com `apply=1`, bipar aparelho já no destino recusa o lote, destino sem checar local ativo/empresa no servidor, entrada por foto avulsa sem recálculo do saldo por local, local pela metade trocado pelo Depósito, "sem local" no lugar de "local removido", lote da tela de Locais sem a orientação da tela nova.
