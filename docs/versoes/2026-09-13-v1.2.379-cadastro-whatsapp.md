## Escopo

O cadastro pelo site exige telefone brasileiro válido e código recebido no WhatsApp. O nome digitado é normalizado e usado ao vincular um cadastro existente compatível; não se tenta adivinhar nomes a partir do e-mail. O cadastro público cria somente perfil CUSTOMER.

Novas contas Google precisam concluir nome, documento e confirmação do WhatsApp. A API restringe a sessão pendente às rotas de conclusão. Contas anteriores permanecem acessíveis; alterar o telefone pelo perfil exige confirmar o novo número.

Código aleatório de seis dígitos, validade de dez minutos, até cinco tentativas, intervalo de um minuto entre envios e limites persistentes por telefone/IP. Código e prova são armazenados como HMAC; a prova é vinculada ao telefone/finalidade/conta e consumida na transação de cadastro. Reenvio invalida a confirmação anterior.

## Validação

- Testes de confirmação: telefone inválido, expiração, cinco erros, reenvio, concorrência, rollback, prova única, limites e cadastro sem bypass.
- Teste local de navegador com API simulada: cadastro bloqueado sem prova, confirmação libera e mudança de telefone invalida; nenhum envio real ou cadastro de teste.
- Regressões existentes de nome, Google, perfil, proxy, autenticação e recuperação de senha.
- Sintaxe dos servidores e módulo; build Vite com trava contra Supabase.
- Um único envio real autorizado; recebimento confirmado pelo operador. Fluxo do novo módulo validado no MySQL com tabelas TEMPORARY, incluindo consumo e bloqueio de replay, sem alterar clientes.
- Após o deploy: conferir API/MySQL, versão pública, página real e rejeições sem envio de WhatsApp.

## Operação e recuperação

Publicar API antes do site. O módulo cria sob demanda duas tabelas InnoDB independentes: `customer_phone_verifications` e `customer_phone_verification_limits`. Elas não são acessíveis pelas rotas genéricas de table-data. Campos de confirmação usam `customers.custom_data`; não há atualização em massa dos clientes.

Rollback coordenado do site e API pelo ponto anterior `v1.2.378-calendar-delete`; preservar tabelas e metadados para auditoria. Reverter a API antiga remove a exigência de confirmação, portanto exige decisão explícita do operador.

O registro específico de nome incorreto não foi editado manualmente: o nome verdadeiro não foi confirmado. Mudanças preexistentes de Android, catálogo, áudio de aniversário e bot ficaram fora desta publicação.
